Failed `/v1` requests return:

```json
{
  "error": {
    "type": "authentication_error",
    "code": "invalid_api_key",
    "message": "Invalid API key provided."
  }
}
```

Session app routes still use `{ "error": { "kind", "message" } }` — only the public API uses `type` / `code`.

## Types

| `type` | Typical HTTP |
| ------ | ------------ |
| `invalid_request` | 400, 404, 409 |
| `authentication_error` | 401 |
| `permission_error` | 403 |
| `rate_limit` | 429 |
| `api_error` | 5xx |

Optional `param` names the field that failed validation (for example `expiresAt`).
