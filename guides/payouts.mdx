A **payout** debits one of your books and pays a [beneficiary](/guides/beneficiaries) on a corridor rail.

## Typical sequence

<Steps>
  <Step title="Ensure a funded book">
    `GET /v1/balances` — available must cover the send amount (fees are carved from it).
  </Step>
  <Step title="Pick corridor + beneficiary">
    [Corridors](/guides/corridors) → create or reuse a [beneficiary](/guides/beneficiaries).
  </Step>
  <Step title="Optional FX quote">
    Cross-currency sends: [firm quote](/guides/fx) then pass `quote_id`.
  </Step>
  <Step title="Fee preview">
    `POST /v1/payouts/fee` with the same shape you will send.
  </Step>
  <Step title="Create">
    `POST /v1/payouts` — returns id and status. Poll `GET /v1/payouts/{id}` or wait for webhooks.
  </Step>
</Steps>

```bash
curl https://api.keette.com/v1/payouts \
  -H "Authorization: Bearer sk_test_…" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: pay-2026-04-01-ada" \
  -d '{
    "beneficiary_id": "…",
    "amount": 50000,
    "currency": "NGN",
    "purpose": "salaries"
  }'
```

Always send a stable **`Idempotency-Key` header** (8–100 characters) so retries do not double-send. Do not put the key in the JSON body.

`purpose` is required. Use a code from `GET /v1/payouts/purposes` (for example `salaries`, `supplier_goods`, `services`). Business workspaces cannot use `family_support`.

## Cancel

`POST /v1/payouts/{id}/cancel` when the payout is still cancellable (`awaiting_auth` or `pending_approval`).

## Purposes

`GET /v1/payouts/purposes` lists allowed purpose codes and document threshold rules for this workspace.
