**Corridors** are the catalog of how money can leave a book: bank rails, mobile money, wires, stablecoins, and more. Use them to drive your UI and to validate beneficiary payloads before create. Bank codes for a country come from a separate utility: `GET /v1/banks?country=…`.

## List

```bash
curl https://api.keette.com/v1/corridors \
  -H "Authorization: Bearer sk_test_…"
```

Optional `country` (ISO 3166-1 alpha-2, e.g. `NG`) returns only corridors that reach that destination. See [Country codes](/guides/country-codes).

```bash
curl "https://api.keette.com/v1/corridors?country=NG" \
  -H "Authorization: Bearer sk_test_…"
```

Each corridor typically includes:

| Field | Meaning |
| ----- | ------- |
| `scheme` | Stable id you send on beneficiaries / payouts (e.g. `ng_nip`, not `ngn_bank`) |
| `currencies` | Supported payout currencies |
| `method` | High-level rail (bank, momo, wire, …) |
| `fields` | Required routing keys (`key` is camelCase, e.g. `bankCode`) |
| `minMinor` / `maxMinor` | Amount bounds when set |

The list response also includes top-level `relationships` codes you may send on beneficiaries — see [Relationships & purposes](/guides/relationships-and-purposes).

## Using corridors

1. Show the customer corridors for the send currency
2. Collect only the fields that corridor requires
3. Create a [beneficiary](/guides/beneficiaries) with that `scheme`
4. Create a [payout](/guides/payouts) against the beneficiary

Corridor availability can differ between live and sandbox keys — always fetch with the key you will use to pay.
